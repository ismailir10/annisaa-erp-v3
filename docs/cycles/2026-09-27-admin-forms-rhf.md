# Admin Forms on react-hook-form + zod (Admin UI Standard — Cycle 2)

## Context
Cycle 1 (`2026-09-26-admin-ui-standard-c1`, ismailir10/annisaa-erp-v3#564) standardised the admin primitives — DataTable mobile contract, `DatePicker`, `RupiahInput`, `AsyncCombobox`, `ConfirmDialog`, `ResponsiveFormDialog`, the unsaved-changes guard. The forms that use them are still hand-rolled. An inventory of `app/admin/**` + `components/admin/**` found ~35 create/edit form surfaces, every one built the same ad-hoc way: one `useState` object, `if (!x) toast.error(...)` checks (or none), a local `saving` flag, and server failures shown only as a toast. So a required field is enforced on one dialog and not the next, an error never points at the field that caused it, and the client rules drift from the zod schemas the API already enforces in `lib/validations/**` (61 client-safe files). That is exactly the "make me think" the owner asked us to remove. The owner chose **react-hook-form + @hookform/resolvers + zod** (new dependency, approved 2026-09-26). `patterns.md` Recipe 3 already mandates "Zod schema + React Hook Form" — the code never caught up. Outcome: every admin field form validates with the same schema as its API route, shows errors inline on the field (with `aria-invalid` + focus on the first invalid field), maps server 400s back onto fields, and uses one submit/pending/cancel footer.

## Spec

### Foundation
- [ ] `react-hook-form` and `@hookform/resolvers` added to `dependencies`; lockfile regenerated by `npm install`.
- [ ] `lib/forms/use-zod-form.ts` — `useZodForm(schema, { defaultValues })` wraps `useForm` with `zodResolver`, `mode: "onTouched"`, `shouldFocusError: true`.
- [ ] `components/ui/form.tsx` — `FormField` built on RHF `Controller` + the existing `components/ui/field.tsx` (`Field`, `FieldLabel`, `FieldDescription`, `FieldError`); no second field system. It owns: generated `id` ↔ `htmlFor`, `aria-invalid`, `aria-describedby` (description + error), `data-invalid` on `Field`, required asterisk + `aria-required`, and the error text. The render prop receives `{ field, fieldState, controlProps }` so the same component binds `Input`/`Textarea` and the controlled widgets (`Select`, `Checkbox`, `Switch`, `RadioGroup`, `DatePicker`, `RupiahInput`, `AsyncCombobox`).
- [ ] `FormRootError` renders `formState.errors.root` inline at the top of the form (Alert, `role="alert"`).
- [ ] `FormDialogFooter` — Batal + submit button bound to `form={formId}`, disabled + "Menyimpan…" while `isSubmitting`, label per `ui.md` (Tambah <Entity> / Simpan Perubahan).
- [ ] `ApiError` gains optional `fieldErrors: { field, message }[]`; `readApiError(res, fallback)` in `lib/api/client-errors.ts` builds it from the standard 400 body `{ error, errors[] }`.
- [ ] `applyServerErrors(form, err, fallback)` in `lib/forms/server-errors.ts`: known field → `setError(field)`; unknown field or non-400 → `setError("root")` + `toast.error(userMessage(err, fallback))`. Never shows raw exception text.
- [ ] Vitest: `form.test.tsx` (label/id wiring, error + aria, one controlled widget of each kind), `server-errors.test.ts`, `client-errors` extension.

### Non-goals
- Grid / wizard editors — not field forms, documented as exceptions: billing-run wizard + line editor, raport editor, report-card narrative templates grid, assessments score grid, Tarif per Program table, themes/subtema/pekan hierarchy, bulk-promote mapping.
- `students/[id]` dossier sub-dialogs (promote, graduate, withdraw, guardian link, primary guardian) — migrated in Cycle 3 when that 2,100-line page is split; doing it now is churn twice.
- Filter bars and search inputs (not submitted forms).
- Teacher and parent portals.
- Any change to what a route accepts or persists, any schema/migration change.

### Assumptions
1. Validate `onTouched` (first error after leaving a field, then live) and on submit; focus moves to the first invalid field. No validate-on-every-keystroke before touch.
2. Where today's client allowed something the API schema rejects (or vice versa), the **API schema wins** on the client — the form now blocks earlier what the server would have rejected anyway. Where the API schema is looser than a rule the client enforces today (e.g. a required field), I keep the client rule in the derived form schema and do not tighten the API.
3. Extracting inline route validation to `validateBody` changes only the 400 **body shape** (adds `errors[]`); status codes and accepted payloads stay the same. Callers that read `body.error` keep working.
4. Keringanan and manual invoice are migrated this cycle (they are real field forms — a discriminated union and a field array are exactly what RHF is for), not deferred with the wizards.
5. `ResponsiveFormDialog` keeps its current props; forms own `<form id>` and pass `FormDialogFooter` as `footer`.
6. The lockfile diff includes npm's `ajv` hoisting reshuffle from `npm install`; it is tooling output, not hand-edited.
7. Branch: designated `claude/serene-mendel-y846yr`, restarted from `origin/staging` (`6258134`) since #564 merged; new PR to `staging`.
