## Severity legend
- **Blocker**: security or scoping leak, data loss, broken core flow, page >4 s / API >2 s / click-to-visible >3 s.
- **Major**: wrong or silently changed data, validation gap, dead end, missing safety step on an irreversible action.
- **Minor**: confusing copy, affordance or layout problems, non-blocking validation gaps.
- **Polish**: cosmetic.

## Summary

139 app findings: **1 blocker, 32 major, 78 minor, 28 polish**, plus 2 seed-data findings. Every page loads under 4 s (median ~1.1 s) and no API call exceeded 2 s. Teacher and parent portals are fast and clear on a phone, and money math is correct end to end. The serious problems sit in the admin tier: a privilege escalation, a sign-out privacy leak, identity records that corrupt each other, and update endpoints that silently reset fields. The existing Playwright suite is fully green (154 passed, 8 skipped). All 8 skips come from seed gaps, and the suite drives none of the paths where the blocker and majors live.

## Fix first

1. **HR-1** (blocker): SCHOOL_ADMIN can grant themselves payroll/HR permissions (privilege escalation). A school admin can quietly grant themselves payroll and employee access, including every salary. Role and user APIs check only 'is some admin'. The privilege boundary between super and school admin is effectively decorative.
2. **PAR-1** (major): Back button after sign-out restores the signed-in profile page. Sign-out then Back shows the previous parent's name, phone, email and children. Shared family phones make this a real privacy leak. The existing regression spec asserts a header and cannot catch it.
3. **HR-4** (major): Deactivating an employee does not revoke their login. Deactivating an employee leaves their login active while the dialog promises the opposite. Staff who leave keep access.
4. **HR-5** (major): Employee email is not unique/synced; creating with an existing email overwrites that user's role. Creating an employee with an existing email rewrites that user's role (school admin became teacher in the run). Silent identity corruption.
5. **X-1** (major): 'Gabungkan dengan wali' creates a duplicate Parent; sibling never appears for existing guardian login. Converting a sibling's admission with 'Gabungkan dengan wali' creates a duplicate parent, so the family's existing login never sees the new child.
6. **CORE-1** (major): Any status change silently resets the admission Sumber to "Datang Langsung". Every admission status change rewrites the inquiry source to 'Datang Langsung', which destroys marketing attribution. Same Zod-4 default-in-partial bug class as DRV-1.
7. **DRV-1** (major): Toggling a journal category/indicator active resets its sort order to 0. Toggling a journal category or indicator on or off resets its order to 0, reshuffling the checklist teachers and parents use daily. Same root cause as CORE-1. Fix the pattern once in lib/validations.
8. **HR-2** (major): Editing attendance variables silently wipes manual line adjustments. Editing payroll attendance variables wipes manual adjustments without warning, so wrong salaries go out.
9. **FIN-6** (major): One click on the primary button records the FULL balance; there is no confirmation and no way to reverse. 'Catat Pembayaran' records the full balance in one click with no confirmation and no reversal path. A misclick marks an invoice Lunas permanently.
10. **TCH-1** (major): Hydration mismatch (React #418): server renders times in UTC, client in WIB. Times render in UTC on the server and WIB on the client: React #418 on every teacher home load, and wrong times for anyone whose device is not on WIB. Pass timeZone: 'Asia/Jakarta' in lib/format.ts.
11. **ACAD-1** (major): Attendance in raport accepts more sick days than school days, no validation. A report card accepts more sick days than school days and publishes it to parents.
12. **X-3** (major): First catatan in a thread never raises an unread badge for the recipient. The first note in a journal thread never raises an unread badge, so a parent's first message to the teacher is effectively invisible.

## Themes (root causes)

- **Update schemas reset fields they were never sent**: Zod 4 applies .default() inside .partial(). Admission source, journal order and (for any partial caller) employee BPJS/bank fields get overwritten on unrelated edits. One lint rule or a shared helper that strips defaults for update schemas closes the whole class. (CORE-1, DRV-1, HR-7)
- **Identity is keyed on email with no uniqueness guard**: Employees, users and parents are matched or upserted by email. Duplicates are accepted, roles get rewritten, and admission merges pick the wrong parent. Staff lifecycle (deactivate) is also not tied to login status. (HR-4, HR-5, X-1, CORE-4)
- **Irreversible money actions without a safety step**: Payments record in one click, cannot be reversed, overdue invoices cannot be voided, and payroll adjustments vanish on recalculation. Finance staff need confirm and undo paths plus an actor on every record. (FIN-6, FIN-7, FIN-9, HR-2)
- **Cross-role signals are missing**: Data reaches the other role correctly, but nobody is told: no first-note badge, no leave decision notice, no new-inquiry surface on the dashboard, and pickup records nobody else can see. The round-trips work but feel silent. (X-3, X-6, X-17, X-21, X-5)
- **Errors surface as 500s, toasts or raw values**: Duplicate codes and names return HTTP 500 with 'Gagal'. Validation lives only in toasts or at the top of the page. Raw enum names, cuids and unformatted numbers leak into messages. voice.md already has the right error contract; these routes don't follow it. (CORE-5, FIN-3, FIN-5, HR-9, ACAD-13, FIN-10, FIN-8, PAR-6)
- **Admin tables don't survive a phone**: Portals are excellent on mobile, but admin lists collapse to near-nothing or clip money and status columns at 390px. Admins will open Talib on a phone between classes. (CORE-7, FIN-21, ACAD-10)
- **Empty states can't tell 'no data' from 'no match'**: Search with no results says 'Belum ada siswa terdaftar, mulai dengan menambahkan…'. That misleads admins into thinking data is gone. (CORE-9, FIN-12)

## Permission matrix (summary)

Teacher and parent are redirected from every admin page and get 403 on every admin API. `u_school_admin` is redirected with no message from HR routes (employees, employee attendance, leave, payroll, salary components, PROMES import) and allowed elsewhere. The gap is inside the admin tier: **HR-1** lets a school admin grant themselves those HR permissions. A few read APIs (config/org, campuses, class-sections, fee-components) return data to parent and teacher sessions (HR-16).

## Limits

- Google sign-in, the OAuth callback and real sessions were not exercised (DEMO_MODE). Auth fixes need signed-in preview verification.

- Agents shared one test DB, so some screenshots show other agents' `E2E-*` rows.
